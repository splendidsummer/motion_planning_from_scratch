# 内层逆解在算什么

[kdl_arm_ik.py](../kdl_arm_ik.py) 里的 `solve_seed()` 只做一件事：手还没放到目标上时，决定每个关节下一步拧多少。选哪只手、肘要不要在身前、会不会碰到桌子，都在这次拧完之后。各库的对照见 [ik_solver_comparison.md](ik_solver_comparison.md)，这一步在整段抓取里的位置见 [kdl_ompl.md](../tutorials/kdl_ompl.md)。

> **先记住三句。** 手要同时对上位置和朝向，手臂却有 7 个关节，所以肘还可以在手里换姿势。内层从一组起始角出发，把这 6 个数拧到手上。手臂快伸直时要拒绝猛拧；关节快转到头时，不能先派活再把超出的部分切掉。

`solve_seed()` 现在按这两句调用 PyKDL。先用 `ChainIkSolverPos_LMA`，6 个权重都是 1，阻尼会随误差放松或拧紧。这组角在 URDF 限位内，并且手已经对上，就留下。角越出限位，或者手还没对上，再用 `ChainIkSolverPos_NR_JL` 加 `ChainIkSolverVel_wdls` 从同一组起始角重解。第二次每拧完一下就把关节夹回限位，阻尼固定为 0.01。肘和左右手仍在这次求解之后才挑。

本文没有在 Gento Skye 上重新计时。`/usr/bin/python3 kdl_arm_ik.py --self-test` 核对了正运动学和往返逆解。

## 这次改了哪一层

外层没有改。换几组起始角、肘在不在身前、左右臂留哪一只、桌子和球交给后面的直线或 OMPL，这些还是原来的函数。改掉的只有 `solve_seed()` 里面「看一眼误差、决定拧多少」。

旧版是脚本自己写的阻尼最小二乘，函数 `damped_pinv()` 已经不在文件里。它每一步都自己做奇异值分解，阻尼只会加大，手靠近之后把肘往起始角拉，关节转到头是加完增量再切掉。

| | 旧的手写循环 | 现在的 `solve_seed()` |
|---|---|---|
| 谁在拧 | 脚本里的循环，最多 160 步 | 先 `ChainIkSolverPos_LMA`，最多 500 步。手没对上或角越出限位，再 `NR_JL` + WDLS，最多 200 步 |
| 阻尼 | 从 0.0001 起，一步被拒绝就乘 5，最大 0.05。只会变大 | LMA 里手更近就放松，手更远就拧紧。第二次重解的阻尼固定为 0.01 |
| 朝向有多重要 | 位置和朝向同一步里一起看，没有把朝向压小 | 6 个权重都写成 1。不用 LMA 默认的朝向权重 0.01 |
| 肘往起始角拉 | 位置差小于 2 cm 且朝向差小于 0.05 rad 之后，增益 0.08 | 不拉。起始角只用来出发，解完再按关节距离挑 |
| 关节限位 | 增量算完再切。切掉的那一截，别的关节同一步里不补 | LMA 的越限答案丢掉。重解时每拧一下就夹回上下限 |
| 一步最多转多少 | 任一关节超过 0.3 rad，整步缩小；误差变大则步长减半，最多 8 次 | 步长由这两个类自己定 |
| 怎样算成功 | 位置小于 0.1 mm，朝向小于 0.0001 rad | 同一把尺子。求解器返回之后，脚本用正运动学再量一次 |

同一条命令、同一组全 0 种子，腰锁在 0：

```bash
/usr/bin/python3 kdl_arm_ik.py \
  --xyz 0.70 -0.18 0.52 \
  --quat 0.31100 0.65408 0.40126 0.56075
```

两次都留下右臂，肘都在身前。手的位置旧版还差大约 0.06 mm，现在差大约 `6.5e-13` m，打印出来就是目标点 `(0.700000, -0.180000, 0.520000)`。7 个角靠近，但不是同一组，因为新版不再把肘拉回起始角，多出来的那个旋钮可以停在别的地方。

| | 旧版 | 现在 |
|---|---|---|
| 右臂位置残差 | `6.318e-05` m | `6.506e-13` m |
| 右臂朝向残差 | `8.470e-05` rad | `0` |
| 离全 0 种子的关节距离 | 1.8995 rad | 1.8977 rad |
| 离最近限位 | 0.3252 rad | 0.3116 rad |
| 正运动学回到 | `(0.699946, -0.180023, 0.519977)` | `(0.700000, -0.180000, 0.520000)` |
| `Joint1_R` … `Joint7_R` | −0.431904，−0.985124，−0.218787，−1.266251，−0.472801，0.721999，−0.234529 | −0.390595，−0.994181，−0.286879，−1.266021，−0.398655，0.735633，−0.274304 |
| 左臂残差 | 0.102 m，0.086 rad | 0.342 m，0.550 rad |

左臂两次都没对上，所以选臂结果仍是 `reason=only_converged`。右臂的 `CURRENT_ORIENTATION`（`0.70710678 0 0 0.70710678`）配同一个点，旧版最近差 `3.985e-02` m 和 `4.014e-01` rad；现在右臂差 `8.531e-02` m 和 `3.257e-01` rad。退出码仍是 2，这个朝向还是不要拿去规划。

## 手要什么，手臂多了什么

目标是夹爪上的一个位姿：空间里的一个点，再加手掌朝哪边。点是 3 个数，朝向是 3 个数，一共 6 个。一条手臂有 7 个能转的关节。

6 个要求、7 个旋钮，会多出一个旋钮没有被「手必须在这里」用完。这个多出来的自由度，看起来就是肘可以绕着换位置，手还停在同一个地方。所以同一个夹爪位姿有一串关节解，不是唯一的一组角。

`solve_seed()` 从其中一组起始角出发，拧到这一串里的某一组。它不负责在这一串里挑肘，也不负责左右手比哪边更合适。

## 内层就是反复看一眼、拧一点

想象手停在半空，目标在桌面上：

1. 看现在的手离目标还差多少，差在位置上，也差在朝向上。
2. 问每个关节：我把它拧一点点，手会往哪个方向动。
3. 按这个答案，挑一组小的拧动，让手更靠近目标。
4. 真的拧过去，再回到第 1 步。

位置差小于 0.1 mm，朝向差小于 0.0001 rad，这组种子才算成功。LMA 内部最多 500 次，限位内的重解最多 200 次。脚本再用自己的正运动学量一遍残差，不拿求解器的返回码当作手已经到了。

第 2 步那张「每个关节拧一点、手往哪动」的表，就是雅可比。它是 6 行 7 列：6 行是手的位置和朝向，7 列是 7 个关节。

## 手臂快伸直时，为什么不能按比例猛拧

手已经快伸直时，有的关节再拧，手几乎不动，只是关节自己在转。雅可比里这个方向的影响很小。

如果求解器按反比去补误差，影响越小，它越要求关节转一大圈，想用手几乎不动的那一下把剩下的误差补完。手臂会突然甩出去。这个姿态叫接近奇异。

LMA 给这种「影响很小的方向」加阻尼。影响小到一定程度，这个方向上的拧动被压得很小，误差留给那些真能带动手的关节。这一步让手更近，阻尼就放松；这一步让手更远，阻尼就拧紧。手臂离开别扭姿态之后，步子可以重新变大。

## 多出来的那个旋钮不再往种子拉

7 个关节对 6 个要求，总有一种拧法几乎不改变手的位置和朝向。肘沿着这条方向转，手还在原地。这就是零空间。

LMA 和 WDLS 都不沿这条方向把肘拉向起始角。起始角仍然有用：求解从那里出发，解完之后外层用离这组起始角的远近，在多组种子里挑。肘在身前是解完之后另一次筛选。

## 关节转到头，越限的那组答案作废

每个关节有 URDF 里的上下限。LMA 不算这个限度。它把位姿解出来之后，脚本量每个角还在不在上下限里面。有一个角越出去了，这组答案就不用，因为若事后把那个角切回来，手就离开了刚刚对上的位置。

接着从同一组起始角调用 WDLS。它在决定「谁来拧」的时候带阻尼，`NR_JL` 每拧完一次就把角度夹回上下限。下一步看到的角度已经是合法的。这次的阻尼是固定的 0.01，手靠近了也不会自动放松。所以它只负责限位内还能不能把位姿解开，不替代 LMA 那次会松会紧的阻尼。

## 为什么是这两个类，而不是一个

PyKDL 1.5.1 里没有一个类同时做完「阻尼会松会紧」和「每一步都留在限位里」。所以脚本按顺序用两个。

LMA 默认更在意手到不到那个点，不太在意手掌朝哪。三个位置的权重是 1，三个朝向的权重是 0.01，朝向在总误差里只占约万分之一。抓取要锁住朝向，脚本把这 6 个权重都设成 1。留着默认值，它可能把夹爪送到点上，掌心却转掉了。

`NR_JL` 加 `pinv_nso` 也能夹限位，也会把关节往一组期望角拉。它补误差的那一步没有阻尼，手臂快伸直时仍会猛拧，所以没有用它。

## 没有阻尼时会发生什么

把阻尼拿掉，影响很小的方向会按反比被放大：这个关节几乎带不动手，求解器就让它转得很大。手臂快伸直时，一个很小的位置或朝向误差，变成关节上的一甩。

PyKDL 里的 `ChainIkSolverVel_pinv`、`pinv_givens`、`pinv_nso` 都是这种没有 $\lambda$ 的补法。它们会把小得过分的方向直接忽略，但刚好还没小到被忽略的方向，仍然会要一个很大的转角。外面再套一层普通牛顿迭代 `ChainIkSolverPos_NR`，也是每一步都用这个放大过的转角。

LMA 和 WDLS 都带着阻尼，所以这一甩被压住了。

## 换掉内层之后，外面这些还在

| 还在外面的事 | 谁在做 |
|---|---|
| 换几组起始姿势再各解一次：当前角、屈肘、`Joint3`、手伸到身前 | `seed_family()` |
| 肘在不在身前 | 解完之后的 `elbow_in_front()` |
| 左右臂留哪一只 | `select_arm()` |
| 桌子、球、方块 | 后面的关节直线和 OMPL |

从一组起始角出发，仍然只得到附近的一组解。LMA 先试。只有这组角越出限位，或者手还没对上时，才从同一起点用 `NR_JL` 加 WDLS 再试一次。

## 公式对照

LMA 和 WDLS 内部仍是阻尼步：雅可比每个方向的影响是 $\sigma$ 时，无阻尼用 $1/\sigma$，阻尼用 $\sigma/(\sigma^{2}+\lambda^{2})$。$\sigma$ 很小时代数结果接近 0，这就是「几乎带不动手的方向别猛拧」。脚本里已经没有手写的 `damped_pinv()`，也没有零空间那一项。

LMA 的默认权重是 $\mathrm{diag}(1,1,1,0.01,0.01,0.01)$，代价是 $E=\Delta x^{\mathsf T} L L^{\mathsf T}\Delta x$。脚本传入的是 6 个 1。它自己的停止条件看的是 $E$，和脚本里分开的 0.1 mm、0.0001 rad 不是同一把尺子，所以解完之后脚本用正运动学再量一次。
